Official Source Lock and Portable Model

docs / design / source-lock-and-model.html

Purpose

Define the version-zero source-lock boundary and version-one portable-model boundary for resolving official NXP sources, verifying immutable locks, and building a downstream-neutral model. ADR-0010 owns the package boundary. The NXP Rust enablement coordination repository owns source-lock, generation-manifest, and override-set schemas. NXP Monkey owns normalized-model schema and migration.

Authorized KEX extension

ADR-0011 authorizes current NXP Monkey JSON/XML as AI-assisted input for the NXP Rust enablement program. Source-lock v0 remains an immutable Git-only contract with KEX marked not-used. A versioned successor acquisition contract records the exact KEX upstream version, variants, archive and file hashes, XML schema identities, JSON-mirror algorithm, and offline replay inputs. Permission to process and generate PAC/SVD artifacts does not by itself authorize committing raw payloads.

Source-lock contract

A version-zero lock contains:

  • requested device, board, and profile;
  • exact manifest URL, commit, content hashes, west version and commands;
  • recursive imports, group filters, complete project inventory, and frozen active-manifest output;
  • full board-reference and consumed-input closures;
  • KEX disposition and governing-license evidence; endpoint/tool/hash fields only when policy permits its use;
  • license-policy revision and per-input disposition references; and
  • a content-derived lock ID independent of generator identity.

Resolution requires an exact commit and delegates recursive-import and selection semantics to the pinned manifest's west extension plus west's parser. The supported baseline records west's resolved active-manifest output as frozen because every included revision is already exact; inaccessible moving entries in inactive groups retain an explicit unavailable status and cannot be selected. Verification derives every selected identity from the pinned manifest, while it caches and checks commits/blobs only for declared consumed inputs with an allowed cache disposition. Offline verification performs no DNS or HTTP access.

Portable model v1

The model has four layers with field-level provenance:

  1. peripheral IP and register blocks;
  2. SoC derivative topology and constraints;
  3. package/SKU availability and pins, with unavailable bond-out facts explicit when no permitted source exists; and
  4. board wiring and resources.

Model v1 excludes account-gated NXP data sheets, schematics, and design archives because no open-source or AI-input permission is retained. It preserves open-source package identifiers without inventing per-package bond-out. No permitted model-v1 source provides complete global pin topology, so every derivative declares its pin scope explicitly; the MCXA board increment is board-required-subset, not a complete topology claim. Board wiring is sourced from the open-licensed BSP and must be confirmed by retained hardware observation.

The MCXA156 board increment requires automated facts for core identity, priority bits, memories/linker regions, interrupts, GPIO, clocks/resets, flash timing, OSTIMER, LPUART0, relevant DMA relationships, capabilities, and LED/VCOM pins. This narrow automation scope does not authorize an incomplete downstream PAC. Non-v1 PAC fields must be separately inventoried as carried/reused in the generation manifest.

Accepted schema v0 remains immutable. Model v1 adds explicit linker conditions, pin-scope policy, source-versus-policy provenance, and truthful flash timing bases. Because those facts cannot be inferred from a serialized v0 model, migration is fail-closed: retain the v0 artifact and re-normalize its immutable source lock with the v1 generator. Runtime model APIs reject v0 rather than silently reinterpret it.

Physical memory inventory and executable integration layout are distinct: memories carries device inventory while linker_regions is parsed from both flash and RAM linker scripts. CMSIS interrupt numbers are primary and are checked against startup vectors and matching SVD facts. A disagreement fails normalization.

The MCXA reproduction inventory is contract-owned and does not shrink when a generated model omits a fact. For MCXA156/MCXA266 it requires priority bits; SCG0, LPUART0, OS_EVENT, and GPIO0-4 interrupts; DMA0, GPIO0-4, PORT0-4, LPUART0, LPUART2, OSTIMER0, MRCC0, and SCG0 instances; and the corresponding generated-Rust register maps. The metadata projection also requires every listed instance gate, both LPUART0 DMA relationships, the exact derivative package identifiers, and the three board-required LED/VCOM pin signals. A comparison oracle missing any required key fails closed; a model missing one emits an unresolved finding.

Reproduction representation rules are exact-value allowlists, not path-wide classifications. Generated-Rust rules bind both measured register-map signatures for each reviewed IP, accounting for generic PAC modules versus derivative-specific SVD availability; any count or hash change is unresolved. Gate rules bind the exact CC-versus-ACC spelling and reviewed PAC adapter configuration names. Portable compatibility is conservative: exact facts are reusable, every known non-exact path is incompatible, and a new path is unresolved. Findings retain an owner, both model/source-lock identities, and competing source locators.

KEX portable model v2

Model v2 is a new contract and does not reinterpret model v1. It consumes only an offline-verified KEX acquisition-lock v1, uses raw XML as hardware authority, and treats the deterministic JSON files as verified projections. The normalizer expands register templates and instances, computes register reset values and masks from their fields, retains interrupts and DMA relationships, and catalogs all package pin routes and programming actions.

Repeated pin-route graphs are content-addressed by semantic content and shared by package pin records; source locators do not affect route identity. Package-specific pin declarations and every package copy of supplementary resource XML are retained as normalized element graphs until dedicated adapters own every concept. Every fact leaf is covered by a source-locator subtree record with a source-value fingerprint; the validator rejects an unknown source, duplicate pointer, missing coverage, invalid range, dangling reference, or changed model ID. CMSIS-SVD-only concepts are not classified until the downstream reconstructability analysis proves them.

When both KSDK and Zephyr binders are locked, their common file identities are recorded and pin programming routes must compare exactly. Binder-only identifiers remain classified metadata rather than silently overriding a hardware route. NXP Config Tools binary model classes may be inspected to confirm vendor parser semantics, but do not supply MCXA156 hardware facts.

Conflicts and overrides

Normalization compares sources by field class and exact scope. Conflicts include stable ID, affected field, source locators and values, classification, owner, disposition, and evidence. Missing required facts, incompatible register shapes, address/interrupt conflicts, or unexplained differences fail. Overrides are exact-scope records with an expected old value and source fingerprint; stale, unmatched, multiply matched, or unused overrides fail.

Generation boundary

NXP Monkey stops at the portable model and semantic reports. A downstream nxp-pac adapter owns nxp-pac metadata and transform policy. Its separate generation manifest names the source lock, model schema, generator revision and command, override-set hash, carried/reused inventory, report IDs, and output hashes.

Determinism and validation

  • Canonical UTF-8 JSON uses sorted keys, two-space indentation, LF, and a terminal newline.
  • Two clean-cache resolutions and normalizations are byte-identical.
  • Offline replay validates every locked commit and content hash.
  • Unknown or unauthorized source state fails closed. ADR-0011-authorized KEX data may enter the AI-assisted workflow, while raw-payload commits require a separate redistribution disposition.
  • Schema changes are versioned and require explicit migration behavior.

Replay is nxp-monkey source verify --lock <lock.json> --cache <cache-directory> --offline. Offline mode forbids DNS, HTTP, and git fetch operations and fails when a required object or blob is missing. Normalization likewise requires --offline and may not perform DNS, HTTP, or git fetch. The v0 resolve command requires an exact manifest commit and --kex-policy not-used.

Canonical identity

Canonical JSON is UTF-8 with sorted object keys, two-space indentation, LF, and one final newline. A record ID is SHA-256 of that canonical document with only its own ID field omitted: lock_id, model_id, manifest_id, or override_set_id. Command arrays preserve argument order and use literal ${CACHE}, ${PROFILE}, ${LOCK}, and ${OUTPUT} tokens instead of host paths.

Unordered arrays use these stable keys:

  • locks: projects by name/path; imports by owner/path; closures lexically; inputs by project/path; groups and license evidence lexically;
  • models: locks and provenance refs lexically; IP blocks by ID; registers by numeric offset/name; fields by bit offset/name; derivatives by device; topology by address/number/ID then name; packages by device/SKU; pins by pad/position; signals by mux/name; boards/resources/provenance/conflicts by ID or type/name;
  • generation: source locks by ID; carried fields by output ID/pointer; applied overrides by override ID/output pointer; reports by kind/ID; outputs by ID; override records by ID; and unordered evidence lexically.

Import chains, manifest group filters, commands, and any other array whose order is semantic preserve source order. A peripheral semantic_hash hashes only its canonical register projection: registers and fields including names, numeric layout, access, reset values, and enumerated values, excluding provenance IDs and descriptions. A value fingerprint hashes the canonical JSON value alone.

Semantic invariants

Schema validation is necessary but not sufficient. The validator requires unique project paths/names and record IDs; every closure/input project must resolve to a selected project; every consumed path is repository-relative; every provenance/source-lock/IP/clock/reset/device/package/board reference resolves; and every consumed input permits generation, redistribution, and AI input. KEX not-used records contain no payload identity. All overrides match exactly once, all carried output pointers exist, and required semantic and completeness reports cover every emitted output. Pre-v2 models' required fact_provenance index maps every carried leaf JSON Pointer to one or more provenance records. Under ADR-0011, model v2 may instead use coverage: subtree: every leaf must have an ancestor provenance pointer, the nearest ancestor defines the leaf's exact source set, and a more-specific record overrides inheritance for that subtree. Every v2 source entry has a resolvable locked-source locator and source-value fingerprint. Validation rejects duplicate pointers, dangling sources, invalid locators or fingerprints, and uncovered leaves.

Normative ownership: ADR-0010. Program retention and serialized schemas: wavenumber-eng-nxp-rust-enablement.
