# NXP Monkey Release 2026-10-22

## [2026.10.22]

Release `2026.10.22` updates certificate trust for NXP HTTPS requests after
the [eMudhra/emSign CA incident](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576).

- Certifi `>=2026.10.19` is now a runtime dependency. Metadata and streamed
  ZIP downloads explicitly use its trust bundle with certificate-chain and
  hostname verification enabled.
- System CA roots and `SSL_CERT_FILE`/`SSL_CERT_DIR` no longer add trusted
  issuers to KEX connections. A corporate TLS inspection proxy that depends
  on a private system CA may need its proxy/trust configuration adjusted.
  There is no insecure fallback when verification fails.
- CLI commands, library signatures, cache layout, and parsed data contracts
  remain stable. Existing cached data is preserved; this patch does not
  establish the integrity of previously downloaded data.
- Development and CI require uv `>=0.13.4`. Isolated build and install tests
  use fixed uv rather than downloading dependencies through seeded pip.
  Linux CI refreshes OS certificates, and the publishing action includes
  upstream's Certifi `2026.10.19` and Sigstore `4.5.1` fix.

Installed users need the new package release to receive the transport fix;
updating the old package's development lockfile alone cannot change its HTTPS
behavior. After publication, update with a verified fixed uv:

```powershell
uv tool install --force "nxp-monkey==2026.10.22"
```

Keep the host OS trust store current and upgrade pip to `>=26.2.2` wherever
it is used. Use the checksum-pinned bootstrap from the incident notice when
starting from an older pip.
